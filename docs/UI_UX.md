# MAGI COMMAND CONSOLE — 화면과 상호작용

이 문서는 Oh My MAGI! macOS 앱의 공통 화면 기하, 심의 과정의 표현, 사용자 조작과 시각적 수용 기준을 소유한다. 개별 화면·상태·전환과 시각 참조는 [전체 UI 계약](UI_SCREENS.md), 제품 범위는 [제품 설계](DESIGN.md), 심의 의미는 [심의 계약](DELIBERATION.md), 실행 상태는 [아키텍처](ARCHITECTURE.md#run-state), 색·서체·컴포넌트는 [디자인 시스템](DESIGN_SYSTEM.md)이 소유한다.

## 1. 화면의 정체성

공개 프로젝트명은 **Oh My MAGI!**다. 콘솔의 표제는 **MAGI COMMAND CONSOLE**, 좁은 화면의 표제와 창 제목·macOS 앱 메뉴는 **MAGI CONSOLE**이다. 공개 프로젝트명은 저장소·배포 정보에 사용하며 콘솔 헤더·푸터·본문의 두 번째 브랜드로 표시하지 않는다.

앱은 별도의 네이티브 사령실 홈으로 시작한다. 홈은 실제 연결·저장 상태, 진행 중 심의와 저장된 최근 기록을 보여 주며 콘솔의 안건 띠나 장면을 흉내 내지 않는다. 새 심의를 선택하면 MAGI COMMAND CONSOLE로 이동한다.

콘솔의 첫인상은 세 컴퓨터가 하나의 안건을 심의하는 거대한 명령 표시장치다. 화면의 골격은 세 코어의 비대칭 다각형, 중앙 MAGI 표식, 굵은 상태 띠와 얇은 연결 회로다. 대기 중에도 이 골격이 화면을 지배한다. 세 개의 같은 직사각형 카드, 말풍선의 연속, 공간을 채우는 가짜 터미널 출력으로 골격을 대체하지 않는다.

강한 표제, 넓은 흑색 여백, 밝은 살구색 코어 면, 앰버 경계와 상태에 따른 색면 전환이 기본 경험이다. 본문·입력·근거는 사용자가 오래 읽을 수 있는 안정된 영역에 둔다. 장식적인 데이터열, 임의의 CPU·신뢰도·동기화 수치, 허구의 경보 코드는 실제 상태로 표시하지 않는다.

[전체 UI 디자인 검토](visuals/console/index.html)는 동일한 HTML·SVG 컴포넌트로 콘솔·자료·연결·역할·기록·공유·복구·설정과 메뉴 막대의 상태를 표현한다. 예시 문구는 모델 실행 결과가 아니며 검토 안내는 앱 영역 밖에 둔다. 제품 화면은 평면 도형·글자·연결선으로 구성한다.

## 2. 화면 구성과 기하

### 2.1 기본 창

제품은 설치형 macOS 데스크톱 앱이다. 메인 창의 최소 콘텐츠 크기는 **1024×720 논리 픽셀**, 권장 크기는 **1440×960 논리 픽셀**이다. 최초 크기와 복원 위치는 현재 디스플레이의 작업 영역과 창 장식을 계산해 정한다. 창은 macOS의 이동·크기 조절·전체 화면·창 닫기 조작을 유지한다. 창 제어 버튼 주변에는 최소 80×32 CSS px의 조작 여백을 확보한다. 아래 CSS 치수는 WebView 확대율 100%를 기준으로 한다.

메인 콘솔을 표시하는 작업 영역은 최소 콘텐츠와 창 장식을 담을 수 있어야 한다. 디스플레이 연결 해제·배율 변경으로 이 조건을 만족하는 화면이 없으면 실행과 마지막 유효 창 위치를 보존하고 메뉴 막대에서 화면 배율 조정·사용 가능한 디스플레이로 복귀를 안내한다. 모바일 크기로 메인 창을 축소하거나 조작부를 화면 밖에 고정하지 않는다.

| 영역 | 기본 크기·배치 | 항상 드러나는 의미 |
|---|---|---|
| 상단 명령 띠 | 폭 1024 이상에서 기본 높이 64, 공통 한 행 | 단일 콘솔 표제, 기록·설정·음향·동작 제어 |
| 안건 띠 | 기본 최소 높이 88, 모든 화면의 동일한 상단 위치 | 현재 질문, 확정 여부, 사용 자료 수, 문맥에 맞는 주 행동 |
| 세 코어 무대 | 헤더·안건·결의·상태 띠를 제외한 가용 영역 | 세 정체성, 관점, 현재 단계, 검증된 의견 또는 공개된 표 |
| 상세 열람 영역 | 명시적으로 여는 문서 보기, 축약 코어와 넓은 본문 | 선택한 코어의 설명, 근거 또는 쟁점 |
| 결의 띠 | 최소 높이 112 | 최종 제안, 표결 결과, 반대·기권·미해결 사항, 후속 질문 |
| 하단 상태 띠 | 최소 높이 32 | 저장 상태, 실행 단계, 경과 시간, 취소·복구 경로 |

높이는 고정된 내용 제한이 아니다. 긴 안건과 큰 글씨는 줄바꿈하고 해당 영역의 높이를 늘린다. 읽는 내용이 넘치면 상세 열람 영역 또는 문서 본문을 스크롤한다. 코어마다 별도 작은 스크롤 창을 두지 않는다.

사령실 홈은 메인 콘솔 셸과 분리된 시작 화면이다. 콘솔 헤더·안건 띠·결의 띠를 홈에 중복 렌더하지 않으며 홈 내용은 자체 문서 흐름에서 읽는다. 새 심의를 선택하면 공통 명령 콘솔 셸에 진입한다.

바깥 여백은 기본 16px다. 헤더는 창 제어 안전 영역 → 단일 표제 → 가변 여백 → 기록 → 설정 → 음향 → 동작 제어 순서를 소유한다. 동일한 창 크기·언어·확대·설정에서 화면 상태가 바뀌어도 높이, 표제 시작점과 기준선, 메뉴 순서와 클릭 영역은 변하지 않는다. 전역 설정 문구가 바뀌어도 버튼 슬롯의 너비를 유지한다.

안건 띠는 레이블 → 질문 → 자료 → 주 행동의 공통 슬롯을 쓴다. 대기에서는 질문 슬롯이 여러 줄 입력이고 이후에는 같은 위치의 읽기 전용 표현이다. 입력 확인·자료 선택·화면 전환이 질문을 하단으로 이동시키지 않는다. 긴 질문은 펼치기 또는 공통 높이 확장으로 읽으며 동일한 질문은 모든 장면에서 같은 확장 규칙을 따른다.

취소는 주 행동과 구별된 위치·스타일의 `심의 취소`다. 하단 실행 조작 영역에 두며 안건 띠의 입력 확인 슬롯에 치환하지 않는다. 하단 상태 띠는 저장·연결·실행 상태의 고정 슬롯을 가지며 허구의 시각·장식 문구로 대체하지 않는다. 연결·사용량을 확인하지 못했으면 미확인으로 표시한다. 근거 열람은 보기 모드이며 실제 실행 상태인 표결 완료·검토 중 등을 대체하지 않는다.

대기·교차 검토·표결 완료는 같은 무대 컴포넌트에 상태만 전달한다. 같은 viewport에서 일반 무대의 원점·크기·스케일은 동일하며 하단 문구 길이로 코어가 위아래 움직이지 않는다. 근거 열람은 동일한 헤더·안건·상태 띠 안에서 무대만 `compact`와 문서 영역으로 바꾼다. 닫으면 이전 선택·질문·읽던 위치로 돌아간다. 상단 영역을 화면별로 재작성하거나 이미지로 복사하지 않는다.

### 2.2 세 코어의 고정 배치

무대의 좌표는 가로 1360, 세로 600인 기준 좌표계다. 아래 범위는 기본 실루엣의 외접 영역이며 실제 색상과 선 두께는 디자인 시스템을 따른다.

| 위치 | 표시 이름 | 기준 영역 `(x, y, width, height)` | 실루엣 |
|---|---|---|---|
| 위 | BALTHASAR-2 | `(240, 10, 880, 315)` | 위쪽 두 모서리와 아래쪽 두 모서리가 잘린 넓은 다각형 |
| 왼쪽 아래 | CASPER-3 | `(10, 235, 625, 360)` | 바깥 세로 면과 중앙으로 내려오는 대각선 상단 |
| 오른쪽 아래 | MELCHIOR-1 | `(725, 235, 625, 360)` | CASPER와 대응하는 바깥 면과 중앙 방향 대각선 |
| 중심 | MAGI | `(595, 342, 170, 148)` | 세 연결 회로가 닿는 결의 표식 |

이 배치는 앱의 일관된 시각적 정체성이다. 역할 이름·모델·판정이 바뀌어도 코어의 위치와 번호를 바꾸지 않는다. 색깔로 코어의 성격을 고정하지 않으며, 어느 코어도 항상 반대하거나 특별한 거부권을 갖지 않는다.

다각형 경로·중앙 간격·텍스트 앵커는 단일 CoreTopology가 소유한다. `normal`과 `compact`는 같은 경로를 사용한다. 축약 시 보조 문구를 숨길 수 있지만 코어명·상태는 인접한 접근 가능한 버튼에서도 확인한다. 상태별로 점 좌표·절단 각도·번호 앵커를 다시 생성하지 않는다. 무대가 안건 띠나 행동 영역을 침범하지 않는다.

각 다각형의 24px 안쪽 안전 영역에 코어명, 사용자 지정 관점, 현재 상태, 한 문장의 검증된 요약, 근거 수, 상세 열기 행동을 배치한다. 대각선과 연결선이 본문을 침범하지 않도록 텍스트 영역을 별도로 잡는다. 전체 의견은 상세 열람 영역에서 읽는다. 제목이 길면 줄바꿈하고 정확한 전체 제목은 상세에서도 제공한다.

중앙 MAGI 표식은 현재 심의 단계 또는 최종 결과를 표시한다. 표결 전에는 찬반 비율을 예측하거나 미리 채우지 않는다. 연결선은 독립 심의 중 끊긴 회로로 표시하고, 교차 검토가 시작되면 연결된다. 선 자체는 장식이며 같은 단계는 텍스트로도 읽힌다.

### 2.3 창 크기와 확대

| 가용 콘텐츠 폭·높이 | 화면 형상 |
|---|---|
| 폭 1440 이상, 높이 960 이상 | 코어 무대를 기본 표시. 근거 열람은 축약 코어·판정 요약·넓은 본문으로 전환 |
| 폭 1024 이상, 높이 720 이상인 그 밖의 창 | 같은 공통 셸과 코어 기하를 유지. 긴 내용과 하단 조작은 세로 문서 흐름으로 확장 |
| 데스크톱 창에서 글자·콘텐츠 확대 | 도형은 같은 삼각 구조를 유지하고 읽기·행동 영역을 재배치. 확대 때문에 생긴 작은 유효 CSS 폭은 접근성 reflow로 처리 |

메인 창에 모바일 폭이나 모바일 탐색 모드를 제공하지 않는다. 큰 화면을 통째로 축소해 글자를 작게 만드는 방식도 사용하지 않는다. 확대 시 코어 탐색기는 축약 실루엣과 코어명·상태를 보존하며, 본문 순서는 BALTHASAR → CASPER → MELCHIOR다. 스크린리더와 키보드의 기본 순서도 시각 순서에 맞춘다. 축약된 장식 도형은 접근성 트리에서 제외하고 동일한 의미의 실제 버튼을 제공한다.

상세 영역을 열거나 닫아도 안건·세 코어 상태·현재 실행 행동은 접근 가능하다. [접근성 기준](DESIGN_SYSTEM.md#8-접근성한국어국제화)의 320 CSS px reflow는 데스크톱 콘텐츠를 확대해 읽는 조건이며 네이티브 창의 최소 폭을 바꾸지 않는다. 고정 결의 띠가 본문이나 포커스를 덮으면 고정을 해제해 문서 흐름으로 옮긴다.

### 2.4 메뉴 막대와 상태 팝오버

macOS 메뉴 막대에는 단색 삼각 코어 아이콘을 표시한다. 아이콘의 접근 가능한 이름과 도움말은 `MAGI CONSOLE`과 실제 실행 단계를 제공한다. 기본 메뉴 막대 표시에 질문·파일명·모델 사용액을 노출하지 않는다. 봉인 단계에서는 아이콘도 찬반 방향을 드러내지 않는다.

아이콘을 누르면 그 위치에 연결된 **상태 팝오버**를 연다. 팝오버는 폭 440, 기본 높이 560 논리 픽셀인 별도 보조 창이다. 글자 확대나 긴 한국어 문구로 세 코어의 라벨·상태·행동을 담을 수 없으면 내용 영역을 내부 스크롤하며, 팝오버 외곽은 440×560 논리 픽셀을 유지한다. 메인 콘솔의 최소 크기 규칙을 공유하지 않는다. 두 표현은 같은 토큰·CoreTopology·공개 실행 상태를 소비하며, 팝오버 전용 요약 위계를 사용한다.

| 영역 | 내용과 행동 |
|---|---|
| 상단 | `MAGI CONSOLE`, 실제 실행 단계, 마지막 상태 확인 시점 |
| 축약 삼각 코어 | 동일한 세 위치·코어명·공개 상태. 표결 전에는 투표 방향을 숨김 |
| 현재 안건 | 현재 심의 또는 마지막으로 선택한 기록의 제목과 원래 실행 시각 |
| 결의 요약 | 공개 후 표 조합·결과·소수 의견. 미응답을 기권이나 완료로 표시하지 않음 |
| 하단 행동 | `콘솔 열기`, `설정`, 명시적인 `앱 종료`. 실행 중에는 구별된 `심의 취소`와 확인 절차 |

마지막 선택 대화에 실행 중인 심의가 있으면 그것을 표시한다. 없으면 가장 최근 시작한 실행 중 심의를 표시하고, 다른 진행 심의는 건수와 콘솔의 기록 목록으로 이동하는 행동을 제공한다. 실행이 없으면 마지막 선택 기록 또는 `안건 대기`를 표시한다. 과거 기록에는 `기록`과 실행 시각을 함께 붙인다. 현재 자료 선택과 안건은 `콘솔 열기`로 이어지며 새 심의를 시작하지 않는다. 팝오버에는 질문 작성·자료 제출·모델 연결 편집을 복제하지 않는다. 해당 작업은 같은 문맥의 메인 콘솔에서 수행한다.

열린 팝오버의 대상은 새 심의의 시작·완료 때문에 자동 교체되지 않는다. 다른 실행은 건수로 알리고, 재열기 또는 사용자의 명시 선택에서만 대상을 다시 정한다. 선택한 기록이 삭제되거나 상태를 확인할 수 없으면 그 이유를 표시하고 해당 실행의 취소를 비활성화한다. 취소 확인은 표시 중인 안건에 고정되며 대상 변경 시 닫힌다.

팝오버를 열 때 최신 저장 상태를 조회하고 같은 이벤트 구독을 연결한다. 연결이 끊기면 마지막 확인 시점과 `상태 확인 중`을 표시하며 완료나 실패를 추정하지 않는다. 숨겨진 팝오버의 장식 렌더는 멈춘다. 열기·닫기·다시 열기는 모델 호출·자료 재전송을 만들지 않는다.

바깥 클릭과 Escape는 팝오버만 닫는다. 키보드로 아이콘에 진입해 열고, 팝오버 안의 조작을 순서대로 수행하고, 호출한 항목으로 돌아갈 수 있다. 메뉴 막대 아이콘은 지속 점멸하지 않는다. 팝오버도 Command/Clear·동작 감소·무음 설정을 공유한다. 창 닫기·Dock 최소화·앱 종료·디스플레이 변경의 동작은 [운영 계약](OPERATIONS.md)이 소유한다.

## 3. 대기와 새 안건

앱은 연결이 없는 상태에서도 네이티브 사령실 홈을 연다. 홈은 연결·저장 상태와 실제 진행 중 심의, 저장소가 제공한 최근 기록 요약을 표시한다. 최근 요약에는 안건·상태·기록 시각만 보여주며 제공되지 않은 표·역할·근거 수를 추정하지 않는다. 기록 조회의 로딩·사용 불가·오류·완료 상태를 구분하고, 완료된 빈 목록에서만 기록 없음 상태를 표시한다. 예시 결과는 실제 기록이나 재생 항목으로 대신하지 않는다. 홈에서 `새 심의 시작`을 선택하면 MAGI COMMAND CONSOLE로 이동해 질문을 입력한다. 자료 선택 영역은 `자료에서 안건 찾기` 진입을 제공한다. 계정 생성이나 세 공급자 연결을 첫 화면의 필수 관문으로 만들지 않는다.

콘솔 진입 연출은 한 번의 경계선 조립과 표제 점등으로 구성한다. 콘솔이 즉시 조작 가능하며 연출이 입력을 가로막지 않는다. `연결 준비됨`은 실제 연결 확인 이후에만 표시한다. 이미 실행 중인 심의를 복원할 때는 부팅 연출을 반복하지 않고 해당 실행과 마지막 확인 시점을 보여준다.

질문 입력은 여러 줄을 지원한다. Enter는 줄바꿈이고, `⌘Enter`는 안건 확인 화면을 연다. 한국어 조합 중에는 둘 다 심의를 실행하지 않는다. 비어 있는 질문에는 실행 행동 대신 입력 안내를 제공한다.

일반 질문은 세 관점이 검토할 답변형 결의문으로 다룬다. 안건 편집에는 목표, 제약, 비교할 선택지와 사용자가 이미 아는 사실을 선택적으로 보완할 수 있다. `자료에서 안건 찾기`는 “이 자료에서 판단이 필요한 쟁점을 찾아줘”라는 답변형 질문을 채우고 같은 입력·전송 확인 화면으로 이동한다. 쟁점 발굴도 정규 심의 한 번이며 숨은 사전 모델 호출을 만들지 않는다. 결과의 논제는 `제안된 안건`으로 표시하며 사용자가 하나를 선택·수정하면 부모와 연결된 새 심의가 열린다.

## 4. 로컬 자료 접수와 실행 전 확인

### 4.1 자료 접수

파일·폴더 드롭, macOS 파일 선택과 붙여넣기는 같은 자료 접수 화면을 연다. 폴더 드롭은 해당 범위의 접근 요청이며 홈 전체나 외부 링크 대상에 대한 권한 확대가 아니다. 파일 접근·추출·반출 규칙은 [보안 계약](SECURITY.md)이 소유한다.

접수 화면은 왼쪽 자료 목록, 가운데 원문 미리보기, 아래 포함 범위와 제외 사유로 구성한다. 작은 창에서는 순서가 같은 탭과 한 열 문서로 바뀐다.

| 자료 행 | 표시 내용 |
|---|---|
| 식별 | 안전한 파일 이름·상대 경로, 형식, 크기 |
| 원본 | 수집 시각, 원본 해시의 짧은 표기와 전체 보기 |
| 포함 | 전체 또는 선택 범위, 모델에 전달할 실제 텍스트·첨부 |
| 변환 | 추출·분할·요약·문자 인식 여부와 원본의 대응 위치 |
| 제외 | 미지원, 권한 없음, 비밀 후보, 크기 초과 등 구체적 이유 |

원본 파일이 있다고 모든 바이트를 모델이 받았다고 표시하지 않는다. 추출·절단·요약된 입력에는 그 사실을 보여주며, 원문과 전달본을 전환해 볼 수 있다. 현재 파일이 바뀌었으면 보존된 수집본과 최신 파일을 구분하고 새 실행 입력으로 갱신하는 행동을 제공한다.

### 4.2 안건 확인

`심의 시작` 앞에는 실제 실행에 사용되는 고정 입력을 확인하는 화면이 있다. 화면은 QuestionSnapshot, ContextManifest, RoleSetSnapshot의 읽기 쉬운 표현을 사용한다. 내부 객체명과 해시는 펼친 상세에서 확인한다.

- 질문·목표·제약과 선택한 자료 범위.
- 세 관점의 목적·검토 기준과 각 관점에 연결한 모델.
- 전달 목적지별 자료 범위와 클라우드 전송 여부. 질문·역할·이전 기록과 코어 사이에 공유되는 평가·결의문도 전송 목록에 포함.
- 심의 순서와 호출 한도, 공급자가 제공한 사용량 정보.
- 동일 모델 사용 여부와 호출 실패 시 복구 방식.

버튼은 `이 입력으로 심의 시작`이다. 드롭·붙여넣기·연결 설정 저장은 이 행동을 자동 실행하지 않는다. 사용량을 알 수 없으면 `제공자가 사용량을 제공하지 않음`으로 표시하며 무제한·무료·정확한 잔여 토큰을 추정하지 않는다.

## 5. 심의 화면과 연출

UI는 [실행 상태](ARCHITECTURE.md#run-state)를 투영한다. 장면 전환이 실제 단계 변경을 지연시키지 않으며, 애니메이션이 끝나야 새 상태를 읽을 수 있는 구조를 만들지 않는다. 표현 이벤트는 실행 ID·순번·단계에 연결해 중복 또는 역순 수신 시 효과를 반복하지 않는다.

| 실제 상태·사건 | 코어와 중앙 표시 | 장면 변화 | 사용자가 할 수 있는 일 |
|---|---|---|---|
| `preparing` | 자료 확인과 고정 입력 준비 | 선택 자료에서 무대로 한 번 들어오는 앰버 선 | 자료·제외 사유 보기, 취소 |
| `awaiting_confirmation` | `INPUT REVIEW / 입력 확인` | 세 코어의 외곽선이 대기 상태로 정지 | 입력 수정, 심의 시작 |
| `independent_review` | 각 코어 `독립 검토 중`, 완료 코어 `의견 준비됨` | 완료된 코어만 색면을 한 번 점등, 코어 사이 선은 끊김 | 검증된 공개 근거 보기, 취소 |
| `cross_review` | `교차 검토`, 실제 제기된 쟁점 수 | 코어 사이 회로가 연결되고 해당 쟁점 경로 한 번 강조 | 상대 의견에 대한 검토·미해결 질문 보기 |
| `synthesis` | 중앙 `결의문 작성`, 코어 의견은 고정 | 중앙 수렴선과 결의문 영역 열기 | 세 의견과 결의문의 대응 확인 |
| `balloting` | 각 코어 `표 제출 대기` 또는 `표 봉인됨` | 제출 완료 코어에 동일한 봉인 표식, 찬반 색 비공개 | 표결 대상 제안 전문 보기, 취소 |
| 모든 유효 표 수신 | 세 표를 같은 화면 갱신에서 공개 | 코어별 찬성·반대·기권 표식과 결의 띠가 함께 전환 | 각 표의 이유·소수 의견 보기 |
| `completed` | 실제 outcome과 확정 제안 | 결의 띠에 한 번의 판정 표식, 이후 정지 | 기록, 재생, 후속 질문, 공유 미리보기 |

첫 독립 의견은 구조·근거 연결을 검증한 뒤 사용자에게 공개한다. 다른 에이전트에 대한 공개 시점은 심의 계약의 장벽을 따른다. 미완료 스트리밍 문장은 펼친 초안 영역에서만 `생성 중 · 미검증`으로 표시하고 검증된 의견이나 표로 취급하지 않는다. 숨겨진 사고 과정을 받거나 재생한다고 표현하지 않는다.

종합 결의문을 작성하는 서기 세션은 MELCHIOR에 연결된 제공자를 사용한다. 화면에서는 `결의문 작성`이라는 단계로 표시하며 네 번째 코어·표·독립 검증자로 추가하지 않는다. 구조·참조 검사를 통과한 후보를 표결 대상으로 동결하고 표결로 진행하며, 조언에 대한 두 번째 사용자 승인을 요구하지 않는다.

표결은 세 코어 모두 동일한 ProposalSnapshot을 대상으로 한다. 일부 표가 먼저 도착해도 사용자와 다른 에이전트에게 방향을 공개하지 않는다. 색·효과음·연결선·실시간 요약이 봉인된 표를 간접적으로 드러내지 않게 한다.

## 6. 결의와 소수 의견

결의 띠에는 표결 대상 제안의 정확한 문구, 세 표, 결과 이름과 확인되지 않은 조건을 함께 표시한다. 종합 설명을 생성하거나 다듬는 과정이 제안이나 표를 변경하지 않는다.

| Outcome | 주 표제 | 필수 보조 표현 |
|---|---|---|
| `unanimous` | `UNANIMOUS / 만장일치 지지` | 찬성 3·반대 0·기권 0과 제안 전문 |
| `majority` | `MAJORITY / 다수 지지` | 정확한 세 표, 반대 또는 기권의 이유 |
| `rejected` | `REJECTED / 제안 부결` | 반대 수, 반대 근거, 다시 검토할 대안 |
| `unresolved` | `UNRESOLVED / 결론 미도출` | 실제 표 조합, 해결되지 않은 질문·조건 |

다수 지지를 `합의 완료`나 만장일치로 표시하지 않는다. 미응답·스키마 실패·연결 실패는 기권이 아니다. 유효 표가 부족하면 `표결 미완료`로 표시하고 최종 outcome을 그리지 않는다. 모델의 찬성은 실행 승인이나 사실 검증의 보증이 아니다.

소수 의견은 결의문 바로 아래 첫 화면에 요약이 보인다. 접힌 상세에만 숨기거나 에러 토스트로 처리하지 않는다. `반대 근거 보기`는 현재 실행의 읽기 전용 상세를 열며 모델 호출이나 새 실행을 만들지 않는다. `조건을 바꿔 다시 묻기`와 `이 자료로 후속 질문`은 새 실행 입력을 만들며 완료된 실행을 수정하지 않는다.

결의 상세 문서는 `제안 → 표결 → 공통 근거 → 의견 차이 → 자료와 가정 → 미해결 사항 → 후속 질문` 순서다. 근거 참조를 선택하면 사용한 수집본의 정확한 위치를 연다. 파일이 삭제되거나 접근이 철회되었으면 그 상태와 보존 가능한 참조만 보여준다.

## 7. 중단·실패·복구

| 상황 | 표시와 동작 |
|---|---|
| `paused` | 중단 이유와 그 이유를 해소하는 행동을 결의 영역에 표시. 이미 완료된 의견을 보존 |
| `interrupted` | 마지막 확인 상태와 외부 요청의 완료 여부 미확인을 표시. 조회·정리 후 허용된 재개만 제공 |
| `cancelling` | `취소 확인 중`; 완료되지 않은 외부 요청 수와 상태 확인 경로를 제공 |
| `cancelled` | `심의 취소됨`; 부분 기록을 읽을 수 있고 최종 판정은 없음 |
| `failed` | 실패 단계·원인·부분 결과·새 실행 만들기를 제공. 반대표와 다른 오류 표식 사용 |
| 한도·인증 문제 | 해당 연결·코어의 원인 표시와 연결 설정으로 돌아가는 경로 제공 |
| 저장 실패 | 저장되지 않은 입력을 유지하고 재시도·안전한 내보내기를 제공 |
| 늦은 응답 | 실행 ID와 유효 단계로 검사한 결과만 반영. 현재 입력·선택·포커스를 덮지 않음 |

고정된 자료·질문·역할·제공자 또는 표결 대상으로 동결된 결의문의 변경은 새 자식 실행을 만든다. 결의문 작성 단계의 초안은 동결 전까지 같은 실행의 산출물로 갱신되며, 사용자 개입으로 방향을 바꾸면 새 실행으로 분리한다. 현재 실행의 입력을 조용히 바꾸는 복구 버튼을 제공하지 않는다. 동일 고정 입력에서 허용되는 일시 중단 해소는 [실행 상태](ARCHITECTURE.md#run-state)의 재개 규칙을 따른다. 인증·한도 문제가 해소되면 사용자가 `심의 재개`를 선택해 미완 슬롯을 진행한다.

화면 닫기, 앱 종료, 절전과 재시작의 실제 실행 의미는 [운영 계약](OPERATIONS.md)이 소유한다. 창 닫기를 완료·취소로 간주하지 않으며, 다음 진입 시 실행 중·중단·취소 확인 중 중 실제 상태를 복원한다.

경고 연출은 실패한 영역의 적색 경계·진단 문구·짧은 상태음으로 구성한다. 의견 차이, 모델의 응답 거절과 기술 실패는 각각 원인을 설명한다. 일반 질문에 도덕적 평가를 붙이는 전면 사이렌이나 허구의 보안 코드로 사용자를 벌주지 않는다.

## 8. 역할·연결·설정

역할 편집은 정확히 세 슬롯을 유지한다. 기본 factory 역할의 표시 이름은 MELCHIOR/Scientist, BALTHASAR/Mother, CASPER/Woman에 대응하며 원본은 선택만 가능하고 읽기 전용이다. 각 슬롯은 기본 코어명 아래 사용자 지정 역할명, 목적, 우선하는 기준, 의문을 제기할 조건과 출력 언어를 편집한다. 기본 관점은 MELCHIOR의 근거·실현 가능성, BALTHASAR의 지속성·돌봄, CASPER의 주체성·대안이다. Scientist·Mother·Woman 이름은 원작 정체성을 위한 라벨이며 판단 규칙은 성별·모성·직업 고정관념에 기대지 않는다. 편집은 factory 역할을 복제해 사용자 프리셋으로 시작하며, 사용자 프리셋은 revision을 확인해 저장한다.

역할 저장은 다음 실행의 RoleSetSnapshot에 사용된다. 진행 중 실행은 고정 역할을 유지한다. 커스텀 역할은 파일 권한·자료 반출·심의 절차·표의 수를 변경하지 않는다.

ACP 연결 프로필은 별칭과 어댑터 선택, 프로필별 앱 관리 홈을 보유한다. 전용 홈 경로는 UI에 표시하지 않는다. 저장된 프로필의 어댑터·홈 바인딩은 불변이며 변경이 필요하면 새 프로필을 만든다. `프로필 설정 가능`은 프로필 저장에 필요한 지원 상태일 뿐 런타임 준비 상태가 아니다. 인증·파일 접근·모델 요청은 선택된 프로필 ID, 어댑터 ID, 전용 홈의 runtime attestation이 정확히 일치할 때만 허용된다. attestation이 없거나 다르면 연결 화면에 구체적인 차단 사유를 보여주고 실행은 막는다.

연결 화면은 코어별 할당과 실제 제공자 프로필을 구분한다. 동일한 모델을 세 역할에 연결하면 `같은 모델을 세 관점으로 사용`을 표시한다. 같은 제공자의 다른 모델을 쓰는 경우에는 제공자 중복과 모델 중복을 구분한다. 세 개의 독립된 전문가나 정확도 향상을 보증하는 문구를 사용하지 않는다.

| 연결 화면 구역 | 내용 |
|---|---|
| 연결 목록 | 사용자 지정 이름, ACP 또는 API 경로, 제공자·모델, 확인 상태 |
| 새 연결 | 설치된 에이전트 선택 또는 실행 파일 지정, 지원되는 공식 인증 경로, 사용자 키 설정 |
| 확인 단계 | 실행 파일·통신·인증·필수 기능·모델 확인을 개별 표시 |
| 역할 할당 | 세 슬롯별 모델, 동일 모델 여부, 실행 순서·동시 실행 가능 여부 |
| 사용량 | 제공자가 알려준 한도·사용량·초기화 시각 또는 미확인 표시 |
| 전송 설명 | 읽는 로컬 범위와 추론 목적지, 알려진 클라우드 전송 여부 |

설정은 긴 폼을 담는 전용 화면이다. 짧은 선택은 팝오버, 한 가지 확인은 모달, 근거 읽기는 상세 열람 영역을 사용한다. 설정에서 돌아오면 안건 초안과 읽던 위치가 유지된다. 인증 비밀은 표시용 상태나 공유 결과에 포함하지 않는다.

## 9. 대화·기록·재생·공유

Conversation은 관련 안건과 자식 실행을 연결한다. 대화 기록은 안건 제목·실행 관계·결과·시각으로 찾고, 선택한 안건을 콘솔 또는 문서 형태로 연다. 후속 질문은 입력한 변경과 사용할 이전 자료를 확인한 새 실행이다. 전체 대화와 로컬 자료를 자동 재전송하지 않는다.

기록은 최종 판정뿐 아니라 중단·취소·실패와 부분 의견도 구분한다. 목록과 홈 요약은 실제 저장된 안건·상태·시각만 표시한다. 선택한 기록의 dossier와 공개 이벤트를 읽을 수 없으면 요약까지만 보여주고 근거·표·재생·역할 snapshot을 만들어 내지 않는다. 완료 기록의 역할·제안·자료 참조는 당시 스냅샷을 표시한다. `같은 입력으로 다시 심의`는 새 실행이며 같은 답이 나온다고 약속하지 않는다.

재생은 저장된 공개 이벤트로 동일 콘솔을 구동한다. `REPLAY / 기록 재생`과 원래 실행 시각을 지속해서 표시하고 속도·일시 정지·단계 이동을 제공한다. 재생은 새 모델 호출·파일 접근·표결을 만들지 않는다. 저장된 공개 이벤트가 없는 경우 재생할 내용을 합성하지 않는다.

공유는 [보안 계약](SECURITY.md)의 공개용 파생본을 미리 보는 흐름이다. 사용자는 제목·설명·근거 표시·익명화 결과를 확인하고 정적 결의 이미지 또는 공개 이벤트 재생 묶음을 로컬로 내보낸다. 자동 게시나 업로드는 발생하지 않는다.

공유 화면은 저장된 심의에서 제거한 항목과 남는 본문을 실제 출력과 같은 렌더러로 보여준다. 원문 경로·인증 정보·비공개 자료·모델 응답에 복사된 민감 문자열을 단순히 패널을 접는 방식으로 숨기지 않는다. 문안을 정제한 공유본에는 `정제됨`과 변경된 범위를 표시하고 표는 원본 결과를 옮긴 것이며 수정 문안의 재표결이 아님을 설명한다. 저장되지 않은 합성 결과는 공유할 수 없다. 반대·기권·미완료 표시는 시각적 연출을 위해 제거하지 않는다.

`공유 재생 열기`는 검증된 데이터 묶음을 독립적인 외부 재생 보기로 연다. `EXTERNAL REPLAY / 외부 공유본`과 `수정 가능한 공유 자료 · 원래 모델 실행은 확인되지 않음`을 지속해서 표시한다. 내 실제 심의 기록으로 합치거나 인증된 결의서 배지를 붙이지 않는다. 공유본의 근거는 포함된 정제 텍스트만 읽으며 원본 경로나 다른 자료를 찾지 않는다. 지원하지 않는 버전·초과·잘못된 참조는 이유를 보여주고 열기를 거부한다. 형식·권한·크기는 [보안](SECURITY.md)과 [운영](OPERATIONS.md)이 소유한다.

## 10. 키보드·입력·알림

| 조작 | 동작 |
|---|---|
| `⌘K` | 현재 문맥의 명령·안건 검색 |
| `⌘N` | 새 안건 초안 열기 |
| `⌘Enter` | 안건 확인 열기. 이미 확인 화면이면 명시된 시작 버튼의 동작 |
| `⌘1`, `⌘2`, `⌘3` | BALTHASAR, CASPER, MELCHIOR 상세 선택 |
| `Tab`, `Shift+Tab` | 문서 순서로 조작 이동 |
| 방향키 | 코어 탐색기·탭·목록의 항목 이동 |
| `Escape` | 최상위 팝오버·모달 닫기. 실행 취소 명령을 자동 발행하지 않음 |

단축키는 OS·보조 기술의 단축키를 가로채지 않으며 메뉴에서도 찾을 수 있다. 모든 전역 단축키는 한국어 조합 중 억제한다. 한글 조합·undo·redo·붙여넣기 중 자동 재렌더로 커서나 입력값을 바꾸지 않는다.

모달은 이름·설명·진입 초점·내부 순환·닫은 뒤 복귀 초점을 제공한다. 근거 상세와 비모달 설정은 읽기 흐름을 유지한다. 비동기 의견·표결·오류가 도착해도 입력 중인 초점을 가져가지 않는다. 완료 알림은 한 번의 요약과 결과로 이동하는 행동을 제공하며 스트리밍 토큰마다 낭독하지 않는다.

| 봉인 표결 | 세 표 공개 전 색·소리·문구·접근성 속성 어느 것도 표 방향을 유출하지 않음 |
| 다수 지지 | 같은 화면에 정확한 표 조합과 소수 의견을 함께 읽을 수 있음 |
| 강한 연출 | 모션을 정지한 화면에서도 실루엣·타이포·색면으로 동일한 정체성이 유지됨 |

| 오류·미응답 | 최종 판정·기권·반대표로 오인되지 않고 원인과 복구 행동을 제공 |
| 실제 근거 | 근거 클릭이 당시 사용 범위로 연결되고 변환·누락·접근 철회를 드러냄 |
| 연결 없는 설치 | 콘솔·초안·설정·저장된 기록을 열 수 있으며 기록이 없으면 빈 상태를 표시 |
| ACP 프로필 | 프로필 설정 지원과 runtime admission을 분리하고, 어댑터·전용 홈 불변성과 정확한 attestation을 설명. 차단이면 인증·파일·모델 요청을 허용하지 않음 |
| 역할 프리셋 | 기본 Scientist/Mother/Woman 매핑은 읽기 전용이며, 사용자 복제·편집·revision 저장이 진행 중 실행의 고정 역할을 바꾸지 않음 |

| 공유·재생 | 원본과 독립된 정제 결과, 재생 표시, 표와 소수 의견이 함께 보존됨 |

독립 시각 검토는 1440×960, 1440×900, 1440×768, 1024×768, 1024×720의 대기·독립 검토·교차 검토·봉인·다수 지지·결론 미도출·실패·재생 장면을 비교한다. 데스크톱 확대·접근성 reflow와 상태 팝오버는 각각 별도로 검증한다. 도식과의 픽셀 일치만으로 통과하지 않으며, 실제 데이터 길이·상태·읽기·조작·접근성을 함께 판정한다.
