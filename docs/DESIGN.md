# 제품 설계

이 문서는 Oh My MAGI!의 정체성, 사용자 가치, 범위와 요구사항을 소유한다. 세부 의미의 정본은 [문서 소유권](../README.md#설계-정본)에 따라 하나의 문서가 소유한다.

<a id="identity"></a>
## 1. 제품 정체성

Oh My MAGI!는 개인의 macOS에서 사용하는 무료 팬 창작 의사결정 콘솔이다. 사용자가 질문과 로컬 자료를 제출하면 세 역할이 독립적으로 검토하고, 서로의 주장에 이의를 제기한 뒤 동일한 결의문을 평가한다. 화면은 이 과정을 MAGI의 세 코어와 중앙 결의 구조로 표현한다.

| 항목 | 계약 |
|---|---|
| 공개 프로젝트명 | `Oh My MAGI!` |
| 저장소·폴더 식별자 | `oh-my-magi` |
| 메인 화면명 | `MAGI COMMAND CONSOLE` |
| 짧은 화면명 | `MAGI CONSOLE` |
| 제품 형태 | macOS 데스크톱 앱, 개인 로컬 데이터, 사용자 소유 모델 연결 |
| 기본 언어 | 설명·근거·조작은 한국어, 코어명과 기계 표제는 영문; 영문 UI도 같은 기능 제공 |
| 제공 방식 | 무료 팬 앱, 프로젝트 기여 코드·문서 MIT |

제품의 두 가지 필수 가치는 **MAGI라고 알아볼 수 있는 시각적 경험**과 **어떤 자료로 어떤 판단을 내렸는지 확인할 수 있는 심의**다. 어느 하나의 완성으로 다른 하나의 결손을 상쇄하지 않는다.

3개의 역할이나 다수결 자체의 신규성·우월성을 주장하지 않는다. 기존 다중 에이전트 연구·제품과의 관계는 [공개 근거](REFERENCES.md#related-work)를 따른다. 이 제품의 설계상 차별점은 로컬 자료 선택에서 근거 확인·이견·결의까지 이어지는 데스크톱 경험과 그 전 과정을 표현하는 MAGI 화면이다.

<a id="people"></a>
## 2. 사용자와 완결된 사용 경험

| 사용자 | 하려는 일 | 완료 시 얻는 것 |
|---|---|---|
| 에반게리온 팬 | 자신의 맥에서 작동하는 MAGI를 경험하고 실제 심의를 기록한다 | 실제 심의·기록 재생과 개인정보 없는 공유물 |
| 개인 빌더·기획자 | 기획서·설계서·코드·회의 기록을 바탕으로 선택을 검토한다 | 출처가 연결된 대안·결의·반대 근거·재검토 조건 |
| 개인 사용자 | 메모와 자료로 자신의 문제를 정리하고 질문한다 | 세 관점의 설명, 부족한 정보, 후속 질문과 이어지는 심의 기록 |
| 역할 작성자 | 목적에 맞게 세 관점과 평가 기준을 설정한다 | 버전이 고정되는 역할 묶음과 재사용 가능한 심의 조건 |

첫 실행의 대표 사례는 사용자가 고른 프로젝트 메모를 바탕으로 “이번 변경에서 가장 먼저 결정할 쟁점은 무엇인가?”를 묻는 것이다. 세 코어는 자료에서 확인한 사실과 추론을 구분해 쟁점을 제시한다. 사용자가 하나를 골라 후속 질문을 보내면 부모 기록과 관계가 연결된 새 심의가 열린다.

자료 없이 질문할 수도 있다. 이때 화면은 외부 근거를 읽은 것처럼 표시하지 않고, 제공된 질문과 모델의 일반 지식에 근거한 응답임을 나타낸다. 사실 확인에 필요한 자료가 없으면 그 결손을 결의서에 남긴다.

## 3. 제품 경계

| 영역 | 제공 계약 |
|---|---|
| 질문·대화 | 자유문장 입력, 답변형·권고형 결의, 부모 심의와 연결된 후속 질문 |
| 로컬 자료 | 사용자가 선택한 파일·폴더·붙여넣기에서 허용된 원문을 캡처하고 인용 |
| 모델 | 사용자가 지정한 기존 CLI·ACP 홈의 구독 인증 연결, 실제 제공자 제한을 표시 |
| 역할 | 정확히 세 코어, 기본 관점과 사용자 정의 역할·평가 기준 |
| 심의 | 독립 검토·교차 검토·결의문 작성·동일 문안 표결·반대와 미결 보존 |
| 기록 | 로컬 보관, 출처 범위 조회, 대화 분기, 재생, 삭제, 명시적 내보내기 |
| 팬 경험 | 강한 콘솔 연출, 실제 기록 재생, 비공개 자료를 제거한 공유 |
| macOS 창 | 데스크톱 콘솔과 메뉴 막대 상태 팝오버, 같은 안건·실행 상태로 복귀 |
| 외부 효과 | 사용자가 요청한 앱 기록·내보내기만 허용; 원본 편집·셸 실행·배포·구매·메시지 발송 권한 없음 |
| 서비스 운영 | 중앙 계정·클라우드 대화 저장·운영자 LLM 게이트웨이·모델 구독 재판매 없음 |

브라우저 서비스, 모바일 클라이언트, 상시 파일 감시, 인터넷 자동 수집, 원격 다중 사용자 협업은 이 제품의 계약에 포함하지 않는다. 후속 행동이 필요한 결론은 사용자가 실행할 항목으로 표시한다.

로컬 연동의 가치는 사용자가 허용한 자료를 원문과 연결해 다룬다는 데 있다. 모든 파일을 무제한 전송하거나, 어떤 모델 구독이든 무제한으로 사용할 수 있다는 약속을 포함하지 않는다. 로컬 파일 접근, 모델 입력 구성, 외부 전송은 [서로 구분되는 권한](SECURITY.md)이다.

<a id="principles"></a>
## 4. 제품 불변 조건

1. MAGI의 세 코어 배치와 중앙 결의가 대기·실행·완료·오류 화면의 시각적 중심을 유지한다. 구체 좌표와 전환은 [콘솔 화면](UI_UX.md)이 소유한다.
2. 화면의 단계·표·근거 수·상태는 저장된 실제 이벤트에서 나온다. 장식이 완료율·정확도·모델의 속마음을 대신하지 않는다.
3. 세 역할의 최초 검토 입력은 같은 질문과 같은 허용 자료다. 역할 차이를 제외한 정보 차이를 숨기지 않는다.
4. 최종 세 표는 같은 결의문 digest에 속한다. 빠진 응답·잘못된 JSON·시간 초과를 기권이나 반대로 만들지 않는다.
5. 다수 지지는 세 유효 표 중 지지 두 표라는 관찰 결과다. 반대와 기권을 구분하고 만장일치·진실·정답 확률로 바꾸어 표시하지 않는다.
6. 결의문, 소수 의견, 보류 근거와 자료의 결손을 함께 보존한다. 사용자가 얻는 결과는 사람이 판단할 수 있는 기록이다.
7. 자료·질문·역할·모델 경로의 변경은 새로운 입력 snapshot과 심의를 만든다. 과거 결의를 현재 자료에 대한 결론으로 덮어쓰지 않는다.
8. 원문 수정과 임의 도구 실행은 심의 권한에 포함되지 않는다. 모델의 요청·역할 프롬프트·자료 본문은 권한을 늘리지 못한다.
9. 모델 연결 없이 저장된 실제 기록만 읽을 수 있다. 기록이 없으면 빈 상태를 표시하며 합성 심의를 실제 결과처럼 제공하지 않는다. 실제 모델 호출의 자격과 비용은 사용자가 확인한다.
10. 소리·동작 감소 상태에서도 동일한 정보와 조작이 존재한다. 감성과 접근성은 함께 만족해야 한다.

<a id="flows"></a>
## 6. 사용자 흐름

| 흐름 | 시작과 종료 | 사용자가 확인하는 것 | 실패·복구 |
|---|---|---|---|
| F01 첫 실행 | 앱 시작 → 안건 대기 콘솔 → 질문·자료 입력 또는 기록 열기 | 실제 연결 상태와 저장 기록 유무 | 기록이 없으면 빈 상태를 표시하고, 연결·자료·역할 설정으로 이동 |
| F02 자료 제출 | 드롭·파일 선택·붙여넣기 → 범위와 전송처 확인 | 포함·제외·발췌·추출 결과, 모델별 목적지 | 읽기 실패·초과·형식 불가를 파일별로 해결 |
| F03 쟁점 발굴 | “무엇을 결정해야 하나?” → 출처와 함께 쟁점 목록 | 사실·가정·분석 범위·추가 정보 | 없는 근거는 명시하고 새 자료를 요청 |
| F04 심의 | 질문 확인 → 세 검토 → 교차 검토 → 결의문 → 표결 | 코어별 공개 근거, 원문, 동일 문안, 결과 | 빠진 응답은 일시정지·실패, 유효 반대는 정상 결과 |
| F05 후속 질문 | 결의서에서 질문·조건 변경 → 새 심의 | 부모 질문·자료·변경점과 새로운 표 | 이전 표 재사용·부모 기록 덮어쓰기 없음 |
| F06 역할 설정 | 기본 관점 선택·사용자 편집 → 세 역할 확인 | 역할 목적·중시 기준·반증 조건·모델 경로 | 권한 지시·중복 ID·잘못된 프리셋 거부 |
| F07 기록과 공유 | 완료·미완 기록 선택 → 조회·재생·내보내기·삭제 | 실제 기록 여부, 포함 자료, 공개 미리보기 | 과거 자료를 다시 보내지 않고 재생; 삭제 경합은 코어에서 직렬화 |
| F08 중단과 재개 | 사용자가 멈춤 또는 연결·앱 장애 → 저장 상태 확인 | 중단된 단계, 비용·원격 종료 확인 수준 | 동일 입력 재개 또는 명시적 새 심의, 늦은 응답은 격리 |

대화는 여러 심의 기록의 연속이다. 한 대화에는 실행 중인 심의가 하나다. 다른 대화의 심의는 공급자별 실행 큐와 [운영 한도](OPERATIONS.md)를 공유한다. 실행 중 입력한 후속 문장은 초안으로 보존하며, 사용자가 현재 실행을 취소하거나 완료한 후 새 심의로 제출한다.

자료·모델·권한이 유지되는 후속 질문도 새 입력 snapshot과 전송 목록을 만든다. 재사용 가능한 동의의 범위와 무효화는 [보안 계약](SECURITY.md)이 결정한다. 사용자에게 노출되는 “재개”와 “다시 심의”는 서로 다른 동작이다.

## 7. 공개·배포·라이선스

프로젝트 기여자가 권리를 보유한 코드와 문서는 MIT로 제공한다. 공식 앱 제공은 무료이며 광고, 모델 사용량 재판매, 팬 기능 유료 잠금과 상업 제품 광고를 포함하지 않는다. MIT가 허용하는 코드 재사용과 팬 앱 운영자의 무료 제공 정책은 서로 다른 대상이다.

원작의 이름·이미지·음원·상표와 제삼자 자산에 대한 권리는 코드 라이선스에서 발생하지 않는다. [권리자의 가이드라인](REFERENCES.md#rights)은 개인의 무료 팬 창작과 특정 공개 형식을 설명한다. 그 문서만으로 소프트웨어 배포 전체의 허가를 추정하지 않는다.

배포자는 자산별 제작자·출처·라이선스·사용 범위를 기록하고, 앱에 포함된 팬 표현의 배포 근거를 확인한다. 공식 캡처·음성·음악·로고를 배포물에 복사하지 않는다. 허가가 필요한 표현은 권리 근거가 확인된 형태로만 릴리스한다. 설계 문서의 완성 판정과 공개 앱의 권리·서명 판정은 각각 독립적이다.

공유물에는 비공식 팬 프로젝트라는 출처와 저장된 실제 기록의 재생 표시를 유지한다. 공유 형식의 개인정보 처리와 실행 권한 차단은 [보안 계약](SECURITY.md)이 소유한다.

## 8. 성공 판정

출시 판정은 [수용 시나리오](SCENARIOS.md#acceptance)에 따른다. MAGI의 실루엣과 움직임, 질문에서 결의까지의 사용성, 자료 근거의 정확한 연결, 중단·복구의 신뢰성을 모두 확인한다.

인지도는 별 개수 하나로 품질을 판정하지 않는다. 제품 화면을 본 사람이 실제 심의 기능을 설명할 수 있는지, 설치·연결·첫 심의를 완료하는지, 결의를 검토하면서 출처와 반대 의견을 실제로 찾을 수 있는지를 관찰한다. 대화·파일 내용이나 사용자 식별자를 기본 수집하지 않는다. 익명 피드백은 사용자가 직접 제출한다.

단일 모델보다 더 정확하다는 주장은 동일 자료·과제·비용 조건의 독립 평가가 있을 때만 그 범위를 붙여 표현한다. 기본 약속은 관점 차이를 드러내고 검토에 필요한 기록을 제공하는 것이다.
