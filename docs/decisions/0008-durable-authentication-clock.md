# ADR 0008 — 인증 대기의 영속 실행 시간 권위

- 상태: 채택
- 결정일: 2026-10-03
- 현재 계약: [실행 수명](../ARCHITECTURE.md#run-state), [실행 한도](../OPERATIONS.md#4-실행-예산과-한도)

## 배경

하나의 심의는 여러 공급자 호출을 수행한다. 최초 연결 이후에도 호출별 구독 인증이 발생한다. 실행 상태가 Running이라는 사실만으로 누적 시간을 계산하면 후속 인증 대기를 모델 실행 시간으로 잘못 포함한다. 세션 생성 의도는 외부 효과의 권위이므로 인증 대기의 시간 표식으로 재해석할 수 없다.

## 검토한 대안

| 대안 | 기술적 효과 | 실패 경계 |
|---|---|---|
| 심의의 도메인 이벤트에 인증 단계를 포함 | 하나의 이벤트 순서 사용 | 공급자 연결 세부사항이 평가·제안·표결의 revision과 결합한다 |
| 별도 형식의 영속 인증 단계 이벤트 | 연결 수명과 공개 결과의 권위 분리 | 계보 검증과 삭제·백업·복원에 같은 저장 트랜잭션 경계가 필요하다 |

## 선택과 근거

인증 대기는 전용 형식의 append-only 이벤트로 기록한다. 시작과 종료는 같은 Run·저장소 세대·실행 claim·단계 token을 고정한다. 실행 권한과 단계 기록을 하나의 트랜잭션에서 검사하므로 오래된 프로세스가 인증 대기를 종료하거나 새 시간 예산을 얻을 수 없다. 이는 권한의 단일 진실과 fencing 원칙을 유지한다.

누적 실행 시간은 영속 Running 구간의 합집합에서 확인된 인증 구간과 겹치는 부분만 뺀다. 병렬 구간은 중복 합산하지 않는다. 인증 성공과 확인된 인증 실패는 다른 종료 형식이다. 종료 근거가 없는 구간은 unresolved이며 재시작이나 cleanup만으로 종료 시각을 만들지 않는다.

인증 준비와 모델 호출은 각각 고정된 유한 기한을 가진다. 동일 세션의 인증을 확인한 뒤 모델 호출 단계로 한 번만 전환한다. 이때 남은 실행 예산을 다시 검사하고 모델 호출 기한을 고정한다. 진행 중인 요청의 기한을 갱신하거나 오래된 watchdog 관측으로 새 단계를 종료하지 않는다. 로컬 프로세스 정지를 원격 결과 완료의 증명으로 취급하지 않는다.

## 결과와 검증

검증은 후속 호출의 인증 대기 제외, Running 구간과의 교집합, 중복·잘못된 token·오래된 claim·역순 시각 거부, 확인된 실패와 미확인 종료의 구분, 재시작 후 시간 보존을 포함한다. 마이그레이션은 기존 이벤트 권위를 보존하며, 삭제와 백업·복원은 새 이벤트의 수명도 관리한다. 모델 단계 전환과 송신 기한은 늦은 watchdog 관측 및 막힌 송신기의 실제 경계에서 검증한다.
