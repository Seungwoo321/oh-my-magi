# ADR 0009 — 실행물 세대의 빌드 출처 입력 수명

- 상태: 채택
- 결정일: 2026-10-03
- 현재 계약: [실행물 검증](../SECURITY.md#provider-verification)

## 배경

런타임 빌드와 앱 리소스 검증은 같은 고정 소스 압축본과 패치된 의존성 lockfile을 사용한다. 런타임 컴파일의 종료만으로 두 입력을 삭제하면 이후 앱 검증이 내용 해시를 확인할 수 없다. 입력의 마지막 소비자는 런타임 컴파일러에 한정되지 않는다.

## 검토한 대안

| 대안 | 기술적 효과 | 실패 경계 |
|---|---|---|
| 고정 소스 압축본과 패치된 lockfile만 세대 입력으로 유지 | 모든 소비자가 실제 내용 해시를 다시 확인한다 | 입력의 소유권과 마지막 소비자를 명시해야 한다 |
| 빌더 기록의 출처 주장만으로 입력을 대체 | 보관할 입력을 줄인다 | 실제 내용 검증이 생산자의 증언으로 바뀌며 추가 서명 권위가 필요하다 |

## 선택과 근거

실행물 세대는 고정 소스 압축본과 패치된 lockfile을 검증 입력으로 유지한다. 내용 주소 지정과 실패 시 차단 원칙에 따라 앱 검증은 실제 바이트의 해시를 기존 고정 값과 대조한다. 출력 파일의 서명과 digest 검사를 함께 유지하며 출처 기록만으로 실제 입력을 대체하지 않는다.

전체 소스 복제본과 컴파일 target은 빌드 소비가 끝나면 제거한다. 검증 입력의 수명은 해당 실행물 세대와 이후 앱 빌드 소비자가 종료할 때까지다. 세대 회수 시 입력도 제거하며 워크트리 회수 아카이브에 재생성 가능한 다운로드나 빌드 산출물을 포함하지 않는다.

기존 입력의 복구는 고정 출처·압축본 해시·패치된 lockfile 해시를 확인하고 필요한 lockfile만 추출한다. 잘못된 경로·link·내용·소유권은 거부한다. 실패하거나 취소된 복구의 임시물은 같은 작업에서 회수한다. 복구 자체가 런타임 재컴파일을 요구하지 않는다.

## 결과와 검증

검증은 입력 누락·내용 변경의 거부, 압축본과 lockfile의 고정 해시, 실행물과 출처 기록의 일치, 성공·실패·취소 시 임시물 회수, 최종 세대 회수 시 입력 삭제를 확인한다. 앱의 리소스 검증과 실제 네이티브 기능 검증은 별도로 수행한다.
