# ADR 0006 — 영속 접수 취소와 실행 계보

- 상태: 채택
- 결정일: 2026-10-02
- 현재 계약: [접수 권위](../ARCHITECTURE.md#admission-requests), [보존·백업·복원](../OPERATIONS.md#6-보존삭제백업)

## 배경

프로세스의 취소 token만 보존하면 재시작이나 같은 멱등 의도의 명령 별칭이 취소된 Start를 다시 실행할 수 있다. 기존 명령 receipt의 형식에 접수 전 취소를 끼워 넣으면 완료 명령의 재생 권위를 훼손한다. 기록 삭제와 백업 복원도 취소 정체성의 수명을 명확히 정의해야 한다.

## 검토한 대안

| 대안 | 기술적 효과 | 실패 경계 |
|---|---|---|
| 메모리 token 또는 TTL로 취소 보존 | 프로세스 안에서 효과를 차단 | 재시작·별칭·만료 뒤 취소된 의도가 재등록된다 |
| 기존 완료 receipt에 다른 취소 형식 저장 | 하나의 테이블에서 조회 | 형식과 완료 재생 의미가 섞인다 |
| 별도 영속 fence와 실행 계보 | 명령 재생과 효과 허가를 분리 | 삭제·복원에서도 계보와 최소 fence를 함께 관리해야 한다 |

## 선택과 근거

접수 전 취소는 전용 형식의 변경 불가능한 fence로 저장한다. 멱등성 원칙에 따라 원래 명령과 같은 키·정규화 의도의 별칭을 함께 차단하며, 완료 receipt의 조회는 새 효과를 만들지 않는다. Run·원문 삭제는 최소 fence를 지우지 않는다. 비밀 최소화 원칙에 따라 fence에는 정체성·digest·참조만 두고 원문이나 실행 token을 저장하지 않는다.

백업은 시점이 고정된 snapshot이다. 이후 취소를 알 수 없는 복원본이 원본의 현재 권위를 승계한다는 대안은 배제한다. 복원한 기록은 보존하되 새 실행 계보를 발급하고 가져온 접수 정체성을 재생 전용으로 고정한다. 이는 취소 상태를 추측하여 만드는 대신 과거 명령에서 새 효과가 생기는 경로를 닫는다. 정상 재시작은 같은 계보의 영속 fence를 유지한다.

## 결과와 검증

검증은 취소 후 원문·Run 삭제와 명령 별칭 재등록 거부, 정상 재시작의 fence 유지, 일관 백업에 포함된 fence 보존, 복원한 접수 binding의 실행 거부, 새 계보·generation·프로세스 token의 분리, 새 사용자 명령의 정상 실행을 포함한다. 백업 이후 원본에 생긴 취소를 복원본이 알고 있다고 표시하지 않는다. 미완 실행의 정지 관측과 취소 receipt는 별개의 권위로 검증한다.
