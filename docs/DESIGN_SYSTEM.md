# 디자인 시스템 — MAGI의 시각 언어

이 문서는 색·서체·간격·도형·동작·음향·공통 컴포넌트와 접근성의 정본이다. 화면 구성은 [UI/UX](UI_UX.md), 표결 의미는 [심의 계약](DELIBERATION.md), 실행 상태와 패키지 경계는 [아키텍처](ARCHITECTURE.md)가 소유한다.

## 1. 시각적 원칙

기본 테마는 짙은 흑색 위에 앰버 명령 띠와 밝은 코어 색면을 배치한 **Command**다. 세 코어의 실루엣, 압축된 큰 영문 표제, 짧은 기계 레이블, 촘촘한 선과 넓은 어두운 여백을 결합한다. 평면 색면·이중 외곽선·절단 모서리가 형상을 소유하며 돌출된 입체 코어와 원근 카메라는 사용하지 않는다.

판정과 전송 방향은 색·문자·도형으로 함께 표현한다. 신호선과 장식 숫자가 실제 근거·사용량·상태처럼 보이지 않게 한다. 네온 번짐은 표제에만 제한하고, 본문·입력·자료 미리보기의 선명도는 유지한다.

모션·음향을 끈 화면도 동일한 MAGI 구조를 가진다. 높은 대비와 평면적인 상태 표시를 사용하는 **Clear** 표현을 제공하며, 이 표현에서도 실루엣·코어 위치·표제 위계를 보존한다. OS의 동작 줄이기와 대비 설정은 최초 렌더부터 반영한다.

## 2. 토큰과 배포 경계

참조 방향은 `primitive → semantic → component`다. 원시 팔레트·크기·시간은 디자인 시스템이 소유하며 컴포넌트와 화면은 의미 기반 슬롯만 사용한다. 토큰은 [DTCG Format 2025.10](https://www.designtokens.org/tr/2025.10/format/)의 타입·값·별칭으로 표현한다. DTCG는 커뮤니티 규격이며 W3C 권고 표준이라고 표기하지 않는다.

| 계층 | 예 | 책임 |
|---|---|---|
| 원시 | `color.amber.500`, `space.6`, `duration.medium` | 색값·척도·단위 |
| 시맨틱 | `surface.console`, `text.primary`, `state.support.fg`, `motion.ballotReveal` | 의미와 실제 사용 가능한 조합 |
| 컴포넌트 | CoreInstrument, VerdictBand, EvidenceInspector | 시맨틱 토큰과 접근 가능한 행동 |

디자인 시스템 패키지가 토큰 검사, CSS·타입 생성, 서체 선언, 공통 컴포넌트와 공개 export를 소유한다. 앱·기록 재생·공유 렌더러는 같은 산출물을 소비한다. 소비자가 내부 토큰 원본을 deep import하거나 화면별로 다시 빌드하지 않는다.

동일 버전의 컴포넌트와 토큰을 배포한다. 별칭 순환·누락·잘못된 타입·테마 슬롯 불일치는 빌드를 실패시킨다. 역할 지침·표·제공자 이름·호출 한도는 도메인 데이터이며 토큰으로 저장하지 않는다.

## 3. 색상과 의미

### 3.1 원시 팔레트

| 원시 이름 | 값 | 용도 |
|---|---|---|
| void | `#0A0A0B` | 전체 바탕 |
| warmBlack | `#191311` | 읽기 영역과 겹치는 패널 |
| amber | `#FF8A3D` | 명령·선택·활성 경계 |
| apricot | `#F2B69B` | 코어 기본 색면 |
| ivory | `#F8EBDC` | 본문·중요 정보 |
| sand | `#C9A58D` | 보조 정보 |
| copper | `#AA7450` | 의미 있는 보조 경계 |
| green | `#80E7A1` | 지지와 완료된 연결 |
| red | `#FF637A` | 반대·부결·오류의 개별 슬롯 |
| cyan | `#A2DDE8` | 교차 참조·정보·초점 |

배경 장식선은 별도 저명도 토큰을 사용할 수 있지만 입력 경계·본문·현재 상태를 대신하지 않는다. 투명도·겹침·CRT 효과를 적용한 최종 합성색으로 대비를 판정한다.

### 3.2 시맨틱 매핑

| 슬롯 | Command 매핑 | 비색 단서 |
|---|---|---|
| `surface.console` | void | 전체 화면 |
| `surface.reading` | warmBlack | 본문 프레임 |
| `surface.core.idle` / `text.onCore` | apricot / void | 코어 이름·관점 |
| `text.primary` / `text.secondary` | ivory / sand | 문서 위계 |
| `border.active` | amber | 이중선과 선택 표식 |
| `focus.ring` | cyan, 배경과 분리된 외곽선 | 연속된 2px 이상 링 |
| `state.support` | green / void | `SUPPORT / 찬성`, 체크 표식 |
| `state.oppose` | red / void | `OPPOSE / 반대`, 대각선 표식 |
| `state.abstain` | ivory / void | `ABSTAIN / 기권`, 빈 원 |
| `state.sealed` | apricot / void | `SEALED / 봉인`, 동일한 봉인 도형 |
| `state.active` | amber / void | 실제 단계명과 진행 표시 |
| `state.info` | cyan / void | 출처·연결 설명 |
| `state.unknown` | sand / void | 물음표와 확인하지 못한 대상 |
| `state.error` | red / void | 오류 아이콘·빗금 경계·복구 행동 |

`state.oppose`와 `state.error`는 별도 슬롯이다. 공통 빨간 계열을 사용해도 반대는 유효한 의견, 오류는 실행 문제라는 문구와 도형이 다르다. `unresolved`는 앰버·기권 표식과 결론 미도출 문구로 표현한다. 연결 성공의 녹색은 그 연결에만 적용하고 전체 심의가 지지된 것처럼 코어를 미리 녹색으로 채우지 않는다.

Clear 표현은 표면·선·효과 슬롯의 값만 교체한다. 테마가 표의 의미·코어 번호·반대 표시를 바꾸지 않는다. forced-colors 환경에서는 OS 시스템 색을 사용하며 색면이 없어도 라벨·윤곽·선택·초점으로 조작한다.

## 4. 서체·간격·도형

### 4.1 타이포그래피

| 역할 | 서체 방향 | 크기·행간 |
|---|---|---|
| 공통 콘솔 표제 | Barlow Condensed, 굵기 700·800 | 기본 48px, 공통 폭 규칙으로 28–48px / 1.0 |
| 코어명·MAGI | Barlow Condensed, 굵기 700·800 | 일반 무대 44–72px, 축약 표현은 별도 탐색 레이블 / 1.0–1.1 |
| 판정·단계의 큰 표식 | 한국어 고딕 + 시스템 명조 장식 표제 | 일반 무대 48–96px / 1.0–1.1 |
| 결의·문서 표제 | Noto Sans KR, 굵기 700 | 24–40px / 1.2 |
| 상태·계기 레이블 | IBM Plex Mono + Noto Sans KR | 12–16px / 1.4 |
| 안건·의견·오류·도움말 | Noto Sans KR, 굵기 400·600 | 기본 16px / 1.65 |
| 근거 원문·식별자 | IBM Plex Mono + Noto Sans KR | 기본 14px / 1.6 |

글자 크기는 제품 선택이며 WCAG가 정한 기본 서체 크기로 주장하지 않는다. 상태·오류·행동에 12px 미만 글자를 사용하지 않는다. 본문을 `scaleX`로 압축하거나 글자마다 색수차를 적용하지 않는다.

영문 기계 표제의 대문자 처리는 표시 레이어에서만 한다. 사용자 질문·파일명·모델명·원문은 대소문자를 바꾸지 않는다. 장식용 일본어는 짧은 분위기 표식으로 사용할 수 있으나 핵심 행동·상태는 선택한 앱 언어로 함께 표시한다. 같은 의미의 장식 텍스트는 중복 낭독하지 않는다.

서체는 [Barlow Condensed](https://raw.githubusercontent.com/google/fonts/main/ofl/barlowcondensed/OFL.txt), [Noto Sans KR](https://raw.githubusercontent.com/google/fonts/main/ofl/notosanskr/OFL.txt), [IBM Plex Mono](https://raw.githubusercontent.com/google/fonts/main/ofl/ibmplexmono/OFL.txt)의 SIL OFL 1.1과 저작권 고지를 함께 묶는다. 외부 CDN을 필요로 하지 않으며 사용 파일·버전·해시를 자산 manifest에 고정한다. fallback은 macOS 한국어·영문 시스템 서체를 포함한다. 폰트 로딩 실패에도 버튼 크기·줄바꿈·전체 코어명이 유지된다. 공식 영상의 글꼴 파일·로고·음원을 추출해 배포하지 않는다.

### 4.2 간격과 형상

간격 척도는 4, 8, 12, 16, 24, 32, 48, 64 CSS px다. 코어 안쪽 안전 여백은 24, 일반 패널은 16–24를 사용한다. 큰 모서리 절단은 24 또는 32, 작은 표식은 8을 기준으로 한다. 일반 컨트롤은 각진 외곽과 최대 2px 반경을 사용한다.

경계선은 보조 1px, 의미 있는 외곽 2px, 선택 강조 3px다. 레티나 배율과 확대에서 선이 사라지거나 이중으로 번지지 않게 렌더링한다. SVG·CSS가 도형을 소유하더라도 텍스트·버튼·입력은 접근 가능한 DOM 요소로 구성한다. 전체 콘솔을 하나의 이미지나 캔버스로 평탄화하지 않는다.

정보 밀도는 기본과 여유의 두 설정이다. 여유 설정은 간격·본문 너비·행간을 늘리며 코어 수·자료·상태를 줄이지 않는다. 본문은 한 줄 45–75자에 대응하는 읽기 폭을 목표로 하고 긴 경로·해시는 줄바꿈 또는 전체 보기로 처리한다.

공통 셸은 `layout.shell.gutter`, `layout.header.minHeight`, `layout.agenda.minHeight`, `layout.windowControl.safeWidth`, `layout.windowControl.safeHeight`, `layout.control.minHeight`를 시맨틱 슬롯으로 소유한다. 기본값과 화면별 허용 변화는 [화면 기하](UI_UX.md#21-기본-창)를 따른다. 상태별 스타일은 공통 셸의 크기·정렬·폰트 값을 덮어쓰지 않는다. 주 행동과 취소는 서로 다른 의미 슬롯을 사용한다.

## 5. 모션과 CRT

모션은 `full`, `reduced`, `off`다. 사용자 설정이 없으면 OS의 동작 줄이기를 따른다. 기본 Command 경험은 OS가 동작 줄이기를 요청하지 않을 때 full이며, 최초 화면부터 전역 동작 제어가 보인다. reduced에서는 이동·확대·스윕을 즉시 상태 전환으로 대체하고, off에서는 모든 장식 애니메이션을 끈다.

| 모션 | 시간·범위 | 사용 사건 |
|---|---|---|
| 경계 조립 | 400–700ms, 한 번 | 최초 콘솔 진입 |
| 코어 활성 | 180–280ms, 한 번 | 실제 해당 코어 작업 시작 |
| 의견 도착 | 240–400ms, 한 번 | 구조 검증된 의견 저장 |
| 교차 회로 | 400–600ms, 한 번 | 교차 검토 진입·쟁점 선택 |
| 봉인 | 160–240ms, 한 번 | 유효 표 접수, 표 방향 비공개 |
| 판정 표식 | 300–500ms, 한 번 | 세 표의 원자적 공개 |
| 오류 강조 | 300–500ms, 한 번 | 새로 발생한 실행 오류 |

실제 상태·본문·접근 가능한 이름은 이벤트 처리와 동시에 갱신한다. 모션이 끝날 때까지 입력·본문을 막거나 완료 응답을 기다리게 하지 않는다. 애니메이션을 건너뛰어도 이벤트 기록·최종 상태는 동일하다.

반복 강조는 필요한 영역의 외곽선에서만 최대 초당 1회, 2주기로 제한하고 이후 정지한다. 전면 명암 반전, 포화 적색 점멸, 스트로브와 무한 CRT 깜빡임은 제공하지 않는다. 여러 효과가 겹친 실제 출력이 [WCAG 2.2의 섬광 기준](https://www.w3.org/TR/WCAG22/#three-flashes-or-below-threshold)을 충족하는지 검사한다. 이 제품 제한을 지켰다는 사실만으로 모든 출력의 섬광 적합을 선언하지 않는다.

CRT 스캔라인은 배경 장식층의 정적 패턴이며 기본 불투명도 상한은 0.035다. 입력·본문·포커스·오류 위에 합성하지 않는다. 표제의 glow 반경은 최대 8px이고 본문에는 적용하지 않는다. 흔들림·랜덤 픽셀 결함·색수차가 내용을 가리거나 권한 오류처럼 보이지 않게 한다.

앱이 가려지거나 백그라운드로 가면 장식 렌더를 중단한다. 복귀 시 누적 효과를 재생하지 않고 최신 상태를 표시한다. progress의 수치가 없으면 단계·경과 시간·마지막 응답을 보여주며 퍼센트를 발명하지 않는다.

## 6. 음향

음향은 독립 설정이며 최초 사용은 무음이다. 콘솔의 `사운드 켜기`는 자체 제작한 짧은 미리보기를 제공하고 선택을 저장한다. 모션 설정이 소리 동의를 대신하지 않는다.

| 사건 | 음향 형태 | 규칙 |
|---|---|---|
| 명령 접수 | 짧은 단음 | 실제 명령 접수 후 한 번 |
| 의견 도착 | 코어별 음색의 짧은 이중음 | 검증된 의견 저장 후 한 번 |
| 표 봉인 | 동일한 중립 클릭 | 모든 표 방향에서 동일 |
| 표 공개 | 최종 결과의 짧은 코드 | 결과 문구와 동시에, 최대 1.2초 |
| 연결·실행 오류 | 낮은 두 음 | 새 오류마다 한 번, 자동 반복 없음 |

글자·토큰마다 타이핑 소리를 내지 않는다. 같은 이벤트가 재전송되거나 기록을 열었을 때 새 알림음을 내지 않는다. 재생은 재생 음향 설정을 따르고 실시간 알림과 섞이지 않는다. 백그라운드·절전 복귀 후 누적된 소리를 재생하지 않는다.

모든 소리는 무음에서도 같은 상태·행동을 제공한다. 개별 음량과 즉시 음소거를 제공하고, 장시간 사이렌·음성 성우 모사·공식 OST·효과음을 기본 자산으로 사용하지 않는다. 자산의 출처와 재배포 권리는 배포 manifest에서 검증한다.

## 7. 공통 컴포넌트 계약

| 컴포넌트 | 책임 | 필수 상태·행동 |
|---|---|---|
| ConsoleShell | 명령·안건·무대·결의·상태 영역 | Command/Clear, reflow, 창 복원 |
| ConsoleHeader | 단일 표제·창 조작 안전 영역·전역 메뉴 | 동일 폭에서 높이·기준선·메뉴 슬롯 고정, 화면 이름 중복 없음 |
| AgendaBar | 질문·확정 여부·자료·주 행동의 공통 슬롯 | 편집/읽기 전용이 같은 위치, 긴 질문의 공통 확장 규칙 |

개별 작업의 배치·상태 조합은 [전체 UI 계약](UI_SCREENS.md)을 따른다. 입력은 값·오류·도움말을 같은 필드에 연결하고 오류 발생 시 레이블이나 전체 화면을 교체하지 않는다. 목록 선택은 행·상세의 같은 객체를 가리키며 비동기 갱신이 편집 중인 필드를 덮어쓰지 않는다. 빈 상태·로딩·복구에는 다음 행동을 제공한다. 진행률을 알 수 없으면 숫자 대신 실제 작업 단계로 표시한다.

버튼 로딩이 끝났다고 실행 성공을 표시하지 않는다. 실행 불가 사유는 옆의 접근 가능한 설명이나 이유 보기 행동으로 찾을 수 있다. 토스트는 보조 알림이며 실패·이견·복구 행동의 유일한 위치가 아니다.

## 8. 접근성·한국어·국제화

목표는 앱이 소유한 전체 WebView UI의 [WCAG 2.2 Level AA](https://www.w3.org/TR/WCAG22/)다. 아래 항목은 주요 실패 경계이며 전체 A·AA 기준을 대체하지 않는다.

메인 창은 [데스크톱 크기 계약](UI_UX.md#21-기본-창)을 따른다. 아래 reflow는 확대 후 유효 콘텐츠 폭에 대한 접근성 조건이다. 모바일 제품이나 모바일 최소 창을 정의하지 않는다. 메뉴 막대 상태 팝오버는 별도 보조 표현이며 같은 접근성 기준을 적용한다.

| 기준 | 제품 판정 |
|---|---|
| 1.4.1·1.4.3·1.4.11 | 색 외 라벨·도형, 일반 글자 대비 4.5:1, 큰 글자 3:1, 필요한 UI 경계 3:1 |
| 1.4.4·1.4.10·1.4.12 | 글자 200%, 320 CSS px reflow와 사용자 텍스트 간격에서 내용·조작 유지 |
| 2.1.1·2.1.2 | 키보드로 자료 선택·심의·검토·설정·공유 수행, 키보드 함정 없음 |
| 2.2.2·2.3.1 | 지속 효과 제어와 합성 출력의 섬광 제한 |
| 2.4.7·2.4.11 | 포커스가 보이고 고정 띠·다각형 clip·sheet에 가려지지 않음 |
| 2.5.7·2.5.8 | 드래그 대안, 포인터 타깃 최소 24×24 CSS px |
| 3.3.1·3.3.2 | 필드 이름·오류 이유·수정 위치 연결 |
| 4.1.2·4.1.3 | 이름·역할·값, 단계별 상태 알림, 초점 보존 |

주요 실행·취소·파일 선택 타깃은 제품 선택으로 높이 40px 이상이다. 모서리를 잘라 실제 클릭 가능 영역이 줄어들지 않게 한다. [APG 모달 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)에 맞춰 진입 초점·키보드 순환·Escape·호출자 복귀를 제공한다.

한국어 조합 중 Enter·단축키·자동 저장이 심의를 실행하거나 커서를 이동하지 않는다. UI 언어와 답변 언어는 독립적이다. 한국어·영어 메시지는 문장 단위로 번역하며 기계 표제의 영문을 읽어야만 행동을 이해하도록 만들지 않는다.

자료의 실제 값·해시·파일명은 locale과 무관하게 보존한다. 날짜·숫자는 locale에 맞춰 표시하고 원래 시각·시간대를 상세에서 제공한다. 양방향 문자와 긴 식별자는 주변 레이블과 격리하고 문자열 원문을 조용히 수정하지 않는다.

## 9. 독립 검증

디자인 시스템은 컴포넌트별 기본·hover·focus·disabled·loading·invalid·empty와 제품 고유 상태를 독립 렌더한다. 동일 viewport의 장면별 헤더·안건·조작부 bounding box와 공통 CoreTopology 경로를 비교한다. 헤더 화면 캡처의 픽셀 비교는 글자·렌더 설정을 고정한 경우에 보조 증거로 사용한다. 실제 지원 WebView에서 한국어·영어, Command·Clear, motion full·reduced·off, 무음, forced-colors 대응을 확인한다.

토큰 검사는 참조·타입·대비 조합을 판정한다. 화면 검사는 긴 내용·폰트 실패·확대·작은 창·고정 영역을 판정한다. 실제 키보드·VoiceOver·한국어 IME 검토를 자동 검사와 별도로 수행한다. 봉인된 표는 DOM 속성·접근성 트리·소리·시각 효과에서도 드러나지 않아야 한다.

공유 출력과 저장된 기록 재생도 같은 시맨틱 상태·폰트·표결 의미를 사용한다. 이미지 출력에는 읽을 수 있는 텍스트 결과를 함께 제공한다. 문서 도식·토큰 JSON·스크린샷 하나만으로 실제 제품의 접근성이나 시각 완성도를 통과했다고 판정하지 않는다.
