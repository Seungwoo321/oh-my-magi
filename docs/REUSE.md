# 상업 프로젝트 인계 — 근거를 남기는 다중 관점 검토

이 문서는 상업 프로젝트의 기획·설계 결정에 응용할 수 있는 계약을 정의한다. 수신 프로젝트가 자신의 제품 문서에 도입할 수 있는 독립된 인계 자료다. 팬 프로젝트의 브랜드·화면·코어명·원작 자산을 상업 기능의 전제로 삼지 않는다.

## 1. 적용 대상과 효용

Wireweave Studio처럼 기획 산출물을 다루는 제품에서는 “이 화면의 책임을 나눌 것인가”, “이 요구사항을 출시 범위에 포함할 것인가”, “설계 대안 중 어떤 것을 채택할 것인가”가 검토 대상이다. 입력 문서와 선택 기준이 존재하고, 서로 다른 관점의 이견이 결정을 바꿀 수 있는 상황에 적용한다.

출력은 결정문, 채택 조건, 근거, 반대 의견과 재검토 조건이다. 여러 모델이 동의했다는 사실을 외부 사실의 검증이나 사용자의 승인으로 대체하지 않는다. 단순 문장 수정처럼 결정 기준과 이견의 가치가 작은 작업에 매번 심의를 강제하지 않는다.

## 2. 인계하는 기능 계약

| 계약 | 수신 제품에서의 사용 | 막는 실패 |
|---|---|---|
| 입력 snapshot | 검토한 요구사항·화면·문서 revision을 고정 | 바뀐 기획에 과거 승인을 그대로 적용 |
| 관점별 독립 초안 | 첫 검토에는 다른 검토자의 결과를 제공하지 않음 | 첫 응답을 모두 따라가는 정보 오염 |
| 주장과 근거의 연결 | 사실·가정·추론·선호를 구분하고 자료 범위 참조 | 그럴듯한 문장을 확인된 사실로 취급 |
| 교차 검토 | 이의의 대상 주장·조건·대안을 식별 | 막연한 찬반과 무조건적 역할극 |
| 고정된 결정문 | 모든 검토가 정확히 같은 문안 revision을 평가 | 검토 뒤 요약 과정에서 의미가 달라짐 |
| 이견과 판단 보류 | 유효한 반대·기권·부족한 응답을 구분 | 장애를 동의로 처리하거나 반대를 삭제 |
| 영속 명령·멱등성 | 제출·재개·취소와 늦은 결과를 명시적으로 처리 | 이중 제출·중복 과금·다른 revision에 결과 귀속 |
| 제한된 실행 예산 | 모델 경로·턴·시간·자료 범위의 상한 | 합의가 나올 때까지 무한 재시도 |

이 계약은 [심의 의미](DELIBERATION.md), [실행 권위](ARCHITECTURE.md), [자료 권한](SECURITY.md)에 대응한다. 수신 제품은 자신의 정본에 필요한 계약을 정의하고 그 문서를 런타임의 단일 진실로 삼는다. 팬 앱 문서를 매번 읽어야 상업 제품이 동작하는 종속 구조를 만들지 않는다.

## 3. 기획 결정의 구체 예시

입력은 화면 설계 revision, 사용자 흐름, 요구사항과 “사용자가 입력을 잃지 않고 되돌아갈 수 있어야 한다”는 기준이다. 관점은 사용자 경험, 구현·운영 가능성, 제품 가치로 구성한다.

각 검토자가 독립적으로 대안을 제안한다. 교차 검토에서 “한 화면으로 합치면 취소 범위가 모호해진다”는 이견이 제기된다. 결정문에는 선택한 화면 구조, 임시 입력의 보관 범위와 취소 의미를 명시한다. 검토 결과는 정확히 그 revision에 붙고, 화면 구조가 바뀌면 재검토 대상이 된다.

이 예시의 가치는 모델 세 개를 호출했다는 사실이 아니라 어떤 조건을 충족하기 위해 어떤 대안을 채택했는지 추적할 수 있다는 데 있다. 사용자 승인이 필요한 업무라면 심의 결과는 `추천` 상태로 남고 사람의 별도 승인을 받아야 실행 상태로 전환한다.

## 4. 수신 프로젝트가 소유하는 결정

| 항목 | 결정 책임 |
|---|---|
| 관점과 검토자 수 | 제품의 도메인 기준에 맞게 정의. 팬 앱의 세 슬롯을 일반 법칙으로 고정하지 않음 |
| 결론 정책 | 자문·다수·전원 승인·지정 책임자 승인 중 업무 의미에 맞게 선택 |
| 외부 행동 | 문서 반영·티켓 생성·배포의 별도 승인, 멱등 키와 보상 계약 |
| 모델 연결 | 해당 제품의 공식 인증 경로·비용·사용자 동의와 정책 증거 |
| 권한과 보존 | 조직·사용자·문서별 접근, 모델 반출, 감사·삭제 의무 |
| 표현과 수익화 | 독립된 브랜드·UI·가격과 코드·서체·자산별 라이선스 |

수신 프로젝트가 미정인 항목은 팬 앱의 동작을 무조건 기본값으로 상속하지 않는다. 해당 프로젝트의 결정 기록에서 의미와 책임을 확정한다.

## 5. 인계 수용 조건

- 검토 기록이 입력 revision과 결정문 digest에 연결된다.
- 미응답과 유효 반대가 구별되고 소수 의견이 승인자에게 보인다.
- 결론 생성과 실제 업무 실행의 권한이 분리된다.
- 동일 revision의 중복 요청과 취소 경합을 결정적으로 처리한다.
- 외부 모델로 전달하는 원문·파생 의견의 범위와 목적지를 사용자가 확인한다.
- 모델의 수 대신 근거 정확성·결손 발견·의사결정 효용을 평가한다.
- 팬 명칭·시각·음원 권한에 의존하지 않고 독립 배포할 수 있다.
